# 简单栈式 VM

先做 VM 的目的不是“最终后端”，而是把编译器前端到执行的链路跑通：

```text
source
  → parser
  → ownership check / lowering（own/borrow/unique、set/push 原地或复制、proof 参数擦除）
  → bytecode
  → VM
```

这样可以在没有 native 后端的情况下验证：

- 证明参数/证明值确实不进入运行时；
- `own`/`unique` 的 `set`/`push` 是否 lowering 成原地；
- 共享值的复制次数；
- 边界检查次数；
- 调用约定、局部变量、控制流是否正确。

## 1. 字节码

```text
PushInt(n) / PushBool(b) / PushUnit
Load(slot) / Store(slot)

Add / Sub / Mul / Neg
Div { checked } / Mod { checked }
Eq / Ne / Lt / Le / Gt / Ge / Not

Jump(target) / JumpIfFalse(target)
Call { func, argc } / Ret

MakeArray(n)
ArrayGet { checked }
ArraySet { in_place }
ArrayPush { in_place }
Len / Print / Pop / Halt
```

- **栈式**：表达式求值结果在操作数栈上。
- **帧**：每个函数调用有独立 `locals`/`stack`/`pc`。
- **调用约定**：参数从左到右压栈，`Call` 弹出 `argc` 个参数，反转后放入新帧的 `locals`；`Ret` 把返回值压回调用者栈。
- **短路**：`&&`/`||` 编译成跳转，不依赖 `And`/`Or` 指令。
- **原地**：`ArraySet { in_place }` / `ArrayPush { in_place }` 由所有权检查结果决定。
- **检查**：当前 `ArrayGet`/`Div`/`Mod` 都是 `checked: true`；后续用证明 facts 改成 `false`。

## 2. 值表示

```rust
enum Value {
    Int(i64),
    Bool(bool),
    Unit,
    Array(Rc<RefCell<Vec<Value>>>),
}
```

- 数组用 `Rc<RefCell<Vec<Value>>>` 共享句柄；原地/复制由字节码变体决定。
- `Int` 是 `i64`；加减乘用 `checked_*`，溢出报错。
- 还没有闭包/字符串/浮点/记录。

## 3. 编译

`src/vm.rs`：

- `compile(&CheckedProgram) -> BcProgram`
- 局部变量槽：参数先分配，`let` 依次分配；不做槽复用。
- `set`/`push` 在所有权检查阶段已经变成 `__set_in_place`/`__set_copy`，编译成对应字节码。
- 用户函数调用按名字解析成函数索引。
- 每个函数末尾自动 `Ret`。

`src/bin/vm_demo.rs`：

```bash
cargo run --bin vm_demo
cargo run --bin vm_demo -- examples/ownership.alt --dump
```

`--dump` 打印反汇编。

## 4. 证明擦除

所有权检查器在生成 `CheckedFn` 时只保留 runtime 参数：

```alethe
fn get(a: Array<Int>, i: Int, h: proof 0 <= i) -> Int { a[i] }
```

编译后的 `get`：

```text
get @0 (arity 2, locals 2)
```

`h` 不在参数里，也不在字节码里。测试 `vm_erases_proof_parameters` 断言 `arity == 2`，并运行 `get(a, 1, by trivial)` 得到 `20`。

## 5. 所有权 lowering

```alethe
fn fill(own a: Array<Int>, x: Int) -> Array<Int> {
  set(a, 0, x)          // __set_in_place
}

fn fill_shared(a: Array<Int>, x: Int) -> Array<Int> {
  set(a, 0, x)          // __set_copy
}
```

`examples/ownership.alt` 在 VM 上的统计：

```text
main = 30
stats:
  allocations:   5
  copies:        2
  in-place ops:  2
  bounds checks: 9
```

与树遍历解释器的结果/统计一致（`vm_matches_interpreter` 测试）。

## 6. 当前限制

- 没有闭包/高阶函数；函数是一等公民之前，先验证基本调用约定。
- 没有 `while`/`match`；递归函数可以工作（`Call`/`Ret`），但没有终止性检查。
- 没有异常/错误传播；运行时错误直接返回 `Err`。
- 数组是 `Rc<RefCell>`，不是无 GC 的最终表示；这是 VM 原型。
- 边界/除零检查始终打开；证明驱动的 `unchecked` 还没有接上。
- 字节码验证器已实现（`verifybc`）：栈高度/类型、局部变量、跳转、调用/返回、数组操作；`vm_demo` 在运行前调用。
- 没有 source map/调试信息。
- 没有 native 后端；Cranelift/LLVM 是后续。

## 7. 字节码验证（已实现）

`src/vm.rs` 的 `verify(&BcProgram)` 在运行前做抽象解释：

- 栈高度与类型一致；
- 局部变量槽初始化/类型；
- 跳转目标在函数内，且目标处状态可合并；
- `Call` 的 argc/参数类型/返回类型匹配；
- `ArrayGet/Set/Push` 的数组元素类型匹配；
- `Ret` 栈上恰好一个返回值，类型等于函数返回类型。

`vm_demo`：

```text
bytecode verification passed
main = 30
...
```

验证器拒绝的用例（单元测试）：

- 栈下溢；
- 返回类型错误；
- 跳转越界；
- 未初始化局部变量；
- 调用参数类型错误。

注意：验证器检查的是**字节码结构/类型**，不是 ProofModel 的定理，也不检查 `in_place` 是否被证明；那属于 `refines`/翻译验证。

## 8. 下一步

1. **IR/ANF**：在字节码前加一层显式 ANF/三地址 IR，方便优化和验证。
2. **字节码验证器**：检查栈高度、跳转目标、局部变量槽，减少 VM 的信任面。
3. **证明 facts 流入**：把 `0 <= i < len(a)` 变成 `ArrayGet { checked: false }`；把 `b != 0` 变成 `Div { checked: false }`。
4. **闭包/高阶函数**：闭包转换 + `MakeClosure`/`CallClosure`。
5. **异常/`Result`**：显式错误传播。
6. **Cranelift/LLVM 后端**：保持同一 IR，替换 VM。
7. **翻译验证**：关键 lowering（原地、布局）产出可检查的等价证书。
